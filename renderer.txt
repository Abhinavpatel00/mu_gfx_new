Render flow (per frame)
=======================

Driver:  src/renderer.c  render_frame()
Scene:   src/three_d/scene.c  scene_frame()
Slimes:  src/three_d/scene.c  slime_record()
Shaders: shaders/*.slang  ->  compiledshaders/*.spv  (loaded from disk at runtime;
         EMBED_SHADERS is disabled in the default make target — see agentcontext §2)

The frame is one command buffer: a chain of compute passes, then the graphics
passes that consume what compute produced. Every pass declares the exact buffer
slices it reads and writes (begin_pass / end_pass + BufferAccess), so barriers
implicate only those byte ranges, never the whole 512 MB pool.

Pass scopes live in perf_report.txt (per-pass ms + verts + frags rows), so the
flow below is documented next to the numbers that justify it.


Compute
=======

Upload (not every frame; only when the relevant table is dirty)
    Instances, mesh rows, group tables, index/vertex arenas   scene_upload_scene
    Bloom strength table                                     (bloom_dirty)
    Wiggle / squash / stretch / face tables                  (only when the slime
                                                              sim is inactive)
    Cull candidate prefix rows                               (candidates_dirty)

Slimes  (once per frame, view 0; only when slime_active)
    Clear hop-grid counts        cmd_fill_buffer  slime_grid_count = 0
    Update slimes                cs_slime_sim     integrate hops -> state_in
    Build hop grid               cs_slime_grid    state_in -> grid (counting sort)
    Resolve collisions           cs_slime_resolve state_in + grid + obstacles -> state_out
                                                  writes instances, squash, stretch, face
                                                  (slime-vs-slime 3x3 + obstacle CSR push-out)
    Ping-pong state              state_in <-> state_out

Cull + compact + route split  (per view)
    Cull                         cs_cull        -> survivors[] (+ survivor_count)
    [MU_NO_SORT off] Depth sort  cs_sort_clear  zero sort_aux (hist + per-bucket cursors)
                 (front-to-back) cs_sort_hist   64 buckets over 256 m, camera from GlobalData
                                 cs_sort_scan   bucket offsets
                                 cs_sort_scatter-> surv_sorted[] (compaction reads this)
    Histogram survivors          cs_count       -> group_count[g]   (reads survivors or
                                                                 surv_sorted)
    Scan per block               cs_scan_block  -> vis_base, cmd_index, scan_aux region 0
                                 (3 lanes: instance count | nonempty | nonempty+alpha)
    Scan block offsets           cs_scan_blocks -> scan_aux regions 1..3
                                 (vis | opaque-draw | alpha-draw block offsets)
    Emit indirect draws          cs_emit        -> draws[] (non-alpha groups),
                                                    draws_alpha[] (alpha-test + FACE groups),
                                                    draw_count[] / draw_count_alpha[],
                                                    group_base[vis_base] = group
                                 Route bit: alpha_bits[g] (uploaded once from material
                                 flags ALPHA_TEST|FACE, scene.c group-build loop).
                                 cmd_index[g] holds the ROUTE-LOCAL slot, so one
                                 per-group array serves two dense command lists.
                                 MU_SPLIT? -> counts[6]: 1 = split (default), 0 = MU_NO_SPLIT
    Scatter survivors            cs_scatter     -> vsrows[] (compacted per-instance rows:
                                                    the VS then does one dependent table
                                                    load per VERTEX, not seven per-slot
                                                    gathers)

Counters copy to the host-visible lane buffer (for the next frame / HUD)
    cs_scan_blocks finalizes DRAWN/FRUSTUM/DRAWS from the scan totals — one write
    per frame instead of one atomic per candidate; cs_emit adds the per-LOD totals.


Graphics
========

Sky
    Draw sky                     pass_sky       -> HDR color (no depth)

Opaque (route split, both passes share ONE indirect structure)
    Draw non-alpha groups        record_scene_draw "Scene Draw"
                                 vkCmdDrawIndexedIndirectCount draws[] / draw_count[]
                                 pipeline: draw_pipeline_early (or toon_pipeline_early)
                                   FS compiled with SCENE_NO_DISCARD: no alpha-test or
                                   face discard in the program, so the driver keeps
                                   EARLY-Z on — depth-failed fragments die before the
                                   FS (this recovered ~25% of frame shading time)
                                 depth: reverse-Z, LOAD_CLEAR 0.0, STORE_KEEP

    MSAA chain (samples > 1): the opaque pass rasters at the chain sample count
    into depth_msaa[]/hdr_color_msaa[] and OWNS the resolves (color AVERAGE,
    depth SAMPLE_ZERO) at its end. Depth LOAD_CLEAR as above.

    Draw alpha-test groups       record_scene_draw "Scene Draw Alpha"  (split only)
                                 vkCmdDrawIndexedIndirectCount draws_alpha[] /
                                 draw_count_alpha[]
                                 MSAA on: draw_alpha_1x_pipeline / toon_alpha_1x_pipeline
                                   — the 1x alpha-test route draws straight onto the
                                   RESOLVED HDR/depth, so grass shading costs once
                                   per PIXEL, not 4x per covered sample (always
                                   created, msaa_scaled=false, sample 1)
                                 MSAA off (default 1x chain): draw_pipeline / toon_pipeline,
                                   the original FS WITH the discards; late-Z by necessity
                                 depth: LOAD_KEEP / STORE_KEEP (occluders final first)
    MU_NO_SPLIT=1 falls back to one combined pass reading draws[] on the original
    pipeline (the pre-split behaviour), for A/B timing.

    Alpha pre-Z scheme (MU_PREZ, default OFF — measured a wash at 678p and
    loses as the scene grows because it re-rasterises the whole alpha list):
    1. "Scene PreZ Alpha" — depth-only pass (color writes off, real discard FS:
       scene_prez.frag / toon_prez.frag via SCENE_PREZ — no lighting after the
       alpha test, depth write is the entire output), LOAD_CLEAR, depth write on.
    2. "Scene Draw" — opaque early-Z route over the seeded depth (LOAD_KEEP:
       leaf geometry now rejects opaque fragments behind it).
    3. "Scene Draw Alpha" — EQUAL-retest pipeline (draw_alpha_eq_pipeline /
       toon_alpha_eq_pipeline, depth compare EQUAL, write on): re-shades only
       texels that survive against the pre-Z depth, pruning leaf-on-leaf
       overdraw. VK: PassDesc.depth_only = true makes begin_pass take a
       graphics rendering path with zero color attachments (color_count == 0
       otherwise means compute).

Transparent
    Draw sparkles additive       scene frame T5b vkCmdDraw(6, slime_count * sparkles_per_slime)
                                 one camera-facing quad per sparkle, procedural
                                 (instance id -> slime -> instance row)
                                 pipeline: sparkle_pipeline (blend ONE,ONE; depth test on, depth write off)
                                 depth: LOAD_KEEP / STORE_KEEP
    Draw particles               (not yet present)
    Draw other transparent       (not yet present)

Post
    SSAO                         pass_ssao          compute
    Bloom                        pass_bloom         compute, BLOOM_MIPS downsample + upsample
    Tonemap / composite          post_pass          compute (tonemap + bloom + ssao + grade)
    SMAA                         pass_smaa
    LDR -> swapchain             pass_ldr_to_swapchain
    Text overlay / UI            pass_text_overlay, nuklear, game HUD


Notes
=====
* Compute pipelines: cs_slime_sim, cs_slime_grid, cs_slime_resolve, cs_cull,
  cs_sort_clear, cs_sort_hist, cs_sort_scan, cs_sort_scatter, cs_count,
  cs_scan_block, cs_scan_blocks, cs_emit, cs_scatter.
* The slime sim runs once per frame for view 0; everything from cull onward runs
  once per view (views[x] live in s->view_frame[view][lane], lane = frame in
  flight). Transients are allocated at the view's first recorded frame, not for
  all views at upload.
* Under the slime sim the dynamic instance prefix [0, 2*slime_count) is owned by
  compute, so the CPU squash/stretch/face uploads are skipped.
* The depth sort and the route split are independent: the sort only reorders
  survivors INSIDE each group's slot range (cs_count histograms groups either
  way), so any combination is valid.
* Env knobs: MU_NO_SORT (skip T2.5), MU_NO_SPLIT (one early-Z-naive draw pass),
  MU_PREZ (alpha depth-only prepass + EQUAL-retest scheme, default off),
  MU_MSAA (startup MSAA 4x; MSAA is opt-in — the Color Grade UI checkboxes are
  the primary control, env only seeds startup state), MU_NO_SMAA,
  MU_SPARKLES=N (0 disables), MU_TOON (pipeline swap), MU_TOON_STYLE,
  MU_FREEZE_TIME (deterministic frames), MU_RES=WxH, MU_PERF=N (headless dump),
  MU_SHOT=N (screenshot after N frames, keeps running).
* Hot MSAA toggle: GraphicsPipelineConfig.msaa_scaled flags sky + the 4 scene
  draw pipelines; pipeline_rebuild_msaa_samples retires and rebuilds them at the
  chain's new sample count; renderer_msaa_apply (device idle) destroys/recreates
  the MSAA rt pair and flips g_msaa_samples. Sparkle and the 1x alpha routes set
  msaa_scaled=false so they never follow the rebuild.
* Negated-Y viewport warning: vk_cmd_set_viewport_scissor rasters with a
  negated Y viewport (bottom-up). Compute-written targets are mirrored in raw
  rows vs rasterized ones. The SMAA-off swapchain route therefore RASTERIZES
  ldr into the swapchain (shaders/blit_swapchain.slang via
  EnginePipelines.swapchain_blit) instead of vkCmdBlitImage'ing the compute
  tonemap output — blitting it showed the scene upside-down. SMAA-on keeps the
  1:1 blit of smaa_final (it re-rasterizes, so it is upright). Do not "fix" the
  negated-Y naively: every rasterized pass in the chain assumes it.
* SPVs are read from compiledshaders/ at pipeline creation; editing a shared
  header (scene_shared.h) does NOT touch their mtimes — rm *.spv before
  measuring anything (agentcontext §7.8).
